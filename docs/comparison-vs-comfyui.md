# 与 ComfyUI 工作流集（Qwen-Image）的横向对比

- **对比对象**：`D:\ai\comfyui-gen-img-workflows-win` → https://github.com/taosapp/comfyui-gen-img-workflows-win
- **本项目**：https://github.com/taosapp/sd-gen-img-win
- **对比日期**：2026-10-16
- **硬件相同**：Dell OptiPlex 7080 / i7-10700K / 32 GB / RTX 3060 12 GB（sm_86）/ Windows

## 数据来源与口径（先说清楚，避免误读）

| 类别 | 说明 |
|---|---|
| 本项目耗时 | **本机实测**（预热 2 次 + 计时 3 次取中位数），原始数据在 `results/bench/bench.csv` |
| 对方耗时 | **其 README 自述**，本次未复测 |
| 出图尺寸 | 本项目基准 512×512；对方基准 720 档（部分 864×1152） |
| 倍数关系 | 尺寸不同，**不应把速度差直接换算成倍数**；下表只作量级参考 |

## 一句话结论

两套不是替代关系：

- **本项目 = 草稿机 + 可编程底座**：512 亚秒级、挡位矩阵可测量、有 HTTP 接口、代码 3722 行可通读。
- **对方 = 成品机 + 中文能力**：Qwen-Image-2.1 中文原生、能在图上写汉字、3 秒抠图、分层图、彩墨风格库。

## 1. 基本盘

| 维度 | `sd-gen-img-win`（本项目） | `comfyui-gen-img-workflows-win` |

| 底座 | diffusers 直调 | 完整 ComfyUI + 2 个自定义节点包 |
| 主模型 | SD 1.5 / SDXL base / SD-Turbo / SDXL-Lightning LoRA | **Qwen-Image-2.1**（GGUF Q5_K_M 4.9 GB）+ Qwen3-VL 8B 文本编码器 |
| 文本编码器 | CLIP（英文语料为主） | Qwen3-VL（**中文原生**） |
| 权重体积 | 16.6 GB | 36.9 GB |

| 代码量 | 36 个 `.py` / **3722 行** | ComfyUI 核心 948 个 `.py` + 1 个自建节点包 |
| 交互形态 | CLI + 网页 + 5 个 HTTP 接口 | 7 个可视化工作流（需在节点图里改参数） |

## 2. 本项目更强的地方

### 2.1 速度与吞吐，快一个数量级

sd-turbo / bf16 / turbo 出 512×512 只要 **0.34 秒**；跑 100 张草稿约 35 秒。
对方最快档 22 秒 / 720，100 张约 37 分钟。

口径不同（512 对 720），但"快速试错、批量挑种子"这个场景，本项目是碾压级优势。

### 2.2 挡位是量出来的产品参数，不是"换个工作流"

4 档精度 × 7 档画质 = 18 组配置，逐项实测耗时与显存占用（17 组可跑通、15 组满足 30 秒预算），
并带**生成前体检**：提前提示 `int(步数×强度)` 只剩 1 步、`CFG≤1` 时负向提示词不生效、中文提示词会被翻译等。

对方要调这些，得进节点图改 KSampler 参数。

### 2.3 可编程

`POST /api/generate`（multipart 上传 + 参数）、`GET /api/jobs/{id}` 轮询、`GET /api/history`、`GET /api/advice` 预检。
能直接塞进脚本、批处理或别的程序。

对方要自动化，得自己构造 ComfyUI 的 `/prompt` 图结构。

### 2.4 可复现

每张 PNG 内嵌元数据：**实际使用的提示词**（中文会记录原文与译文）、模型、精度、画质档、种子、步数、耗时。
换个时间点也能 1:1 复现。

### 2.5 轻，且改得动

省 20 GB 磁盘；3722 行代码能通读，改一处不用在 948 个文件里定位。

## 3. 对方更强的地方（这部分不能含糊）

### 3.1 中文原生 + 图上写字 —— 硬差距

Qwen-Image-2.1 直接理解中文，**能在画面上写出汉字**（海报标题、标语）。
本项目的 SD 系模型做不到：词典只能把"水彩风格"翻成英文，写"母亲节快乐"这类文字渲染无解。

### 3.2 画质上限

Qwen-Image-2.1 的成片质量高于 SD 1.5 / sd-turbo。本项目的 512 是"快而糙"的定位。

### 3.3 功能广度

3 秒抠图（BiRefNet，透明 PNG）、分层出图、彩墨风格库（`styles/` 丢一个 txt 就多一种风格）、
任意加节点（ControlNet / inpaint / upscale）。

## 4. 怎么选

| 你的目标 | 建议 |
|---|---|
| 批量出草稿、快速试提示词与构图 | **本项目** |
| 把生图接进脚本 / 服务 / 别的程序 | **本项目** |
| 需要精确记录参数、可复现 | **本项目** |
| 要海报成品、图上要有中文文字 | **对方** |
| 要抠图、分层图、彩墨等特定风格流水线 | **对方** |
| 显存/磁盘紧张（想省 20 GB） | **本项目** |

## 5. 推荐组合用法

1. 用本项目 0.3 秒一版的节奏，试构图、试提示词、挑种子，筛出 1–3 个候选；
2. 把选中的 `(提示词, 种子, 尺寸, 强度)` 带进对方的工作流出 720/1024 终稿。

> 可选的下一步：写个小工具，把本项目的参数直接生成对应的 ComfyUI 工作流 JSON，
> 省掉手动填节点。（尚未实现）

## 6. 一个有意思的呼应

两套独立开发，却踩到同一个坑：**`CFG = 1.0` 时负向提示词不参与计算**。

- 本项目：`advice.py` 在 `guidance ≤ 1` 时提示"负向提示词不会生效"；
- 对方：README 里写 `comfy/samplers.py:610` 在 cfg=1.0 时把负向条件直接置 `None`，并给出对策——把约束写进正向。

说明这类蒸馏/极速档的共性限制，与框架无关。
